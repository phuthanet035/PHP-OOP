รายงานสรุปรายละเอียดโปรเจกต์เว็บสั่งพิมพ์งาน
(ตามหลัก OOAD & OOP)

1. ภาพรวมของโปรเจกต์

โปรเจกต์นี้เป็นการพัฒนาระบบสั่งพิมพ์งาน (Printing Service) ขนาดเล็กด้วยภาษา PHP โดยอ้างอิงจากแผนภาพคลาส (Class Diagram) ที่กำหนดให้ และประยุกต์ใช้หลักการ Object-Oriented Analysis and Design (OOAD) และ Object-Oriented Programming (OOP) เพื่อให้โค้ดมีโครงสร้างที่เป็นระเบียบ ยืดหยุ่น ต่อการบำรุงรักษาและขยายต่อในอนาคต

2. หลักการ OOP และ OOAD ที่นำมาใช้

2.1 Abstraction (นามธรรม)

การดึงเฉพาะคุณลักษณะและพฤติกรรมที่จำเป็นมาสร้างเป็นโครงสร้างหลัก เช่น การสร้าง ServiceInterface เพื่อกำหนดว่าบริการทุกประเภทต้องมีฟังก์ชันคำนวณราคา (calculatePrice) และการดึงชื่อบริการ (getName)

2.2 Encapsulation (การห่อหุ้ม)

การซ่อนข้อมูล (Data Hiding) และตรรกะการทำงานไว้ภายในคลาส ตัวอย่างเช่น คลาส Paper มีฟังก์ชัน getPrice() ที่ห่อหุ้มตรรกะการคำนวณราคากระดาษเอาไว้ ภายนอกไม่จำเป็นต้องรู้ว่าคำนวณอย่างไร เพียงแค่เรียกใช้งานฟังก์ชันก็จะได้ราคาที่ถูกต้อง

2.3 Polymorphism (พ้องรูป)

ความสามารถในการใช้โครงสร้างเดียวกันแต่ให้ผลลัพธ์การทำงานที่ต่างกัน ตัวอย่างเช่น PrintService และ FinishingService ต่างก็ implements ServiceInterface เมื่อระบบเรียกใช้ calculatePrice() ของบริการใดๆ ผลลัพธ์ที่ได้จะขึ้นอยู่กับว่าเป็นบริการประเภทใดโดยที่ส่วนที่เรียกใช้งานไม่ต้องแยกเงื่อนไข (If-Else) ให้วุ่นวาย

2.4 Composition (องค์ประกอบ)

การที่คลาสหนึ่งถูกสร้างขึ้นมาจากคลาสอื่น ตัวอย่างในระบบนี้คือคลาส Order ที่มีความสัมพันธ์แบบ Composition กับ OrderItem (ตามสัญลักษณ์ข้าวหลามตัดทึบใน UML) หมายความว่า 1 คำสั่งซื้อ (Order) สามารถประกอบไปด้วยหลายรายการย่อย (OrderItem)

3. คำอธิบายรายละเอียดของแต่ละส่วน (Class Details)

3.1 PaperSize (Enumeration)

  • หน้าที่: กำหนดค่าคงที่สำหรับขนาดกระดาษ (A4, A3) ป้องกันการป้อนข้อมูลผิดพลาด (Type safety)
  • ความสัมพันธ์: ถูกเรียกใช้เป็นชนิดตัวแปรในคลาส Paper

3.2 Paper (Class)

  • หน้าที่: เก็บข้อมูลกระดาษ ได้แก่ ขนาด (PaperSize) และชนิด (เป็นกระดาษแข็งหรือไม่)
  • เมธอดสำคัญ: getPrice() ใช้คำนวณราคากระดาษตามขนาดและชนิด (A3 จะแพงกว่า A4 และกระดาษแข็งจะมีค่าใช้จ่ายบวกเพิ่ม)

3.3 ServiceInterface (Interface)

  • หน้าที่: กำหนดข้อตกลงมาตรฐานสำหรับคลาสบริการ (Service) ใดๆ ก็ตามที่อยากจะเชื่อมต่อกับระบบนี้
  • เมธอดที่บังคับให้มี: calculatePrice(Paper, pages, quantity) และ getName()

3.4 PrintService (Class)

  • หน้าที่: บริการงานพิมพ์ (สืบทอดแบบ implements จาก ServiceInterface)
  • คุณสมบัติเพิ่มเติม: เก็บข้อมูลประเภทการพิมพ์ และรูปแบบการพิมพ์สี (isColor)
  • เมธอดสำคัญ: calculatePrice() คำนวณราคาโดยบวกรวมราคากระดาษกับราคาฐาน (Base price) ซึ่งการพิมพ์สีจะมีราคาฐานแพงกว่าขาวดำ จากนั้นนำไปคูณจำนวนหน้าและจำนวนชุด

3.5 FinishingService (Class)

  • หน้าที่: บริการเข้าเล่ม (สืบทอดแบบ implements จาก ServiceInterface)
  • คุณสมบัติเพิ่มเติม: เก็บข้อมูลราคาเข้าเล่มต่อหน่วย (unitPrice)
  • เมธอดสำคัญ: calculatePrice() คำนวณราคาแบบเหมา โดยนำราคาต่อหน่วยคูณกับจำนวนชุด

3.6 OrderItem (Class)

  • หน้าที่: เป็นรายการสินค้า 1 รายการย่อย
  • ความสัมพันธ์: ประกอบด้วย ServiceInterface, Paper, จำนวนหน้า (pages) และจำนวนชุด (quantity)
  • เมธอดสำคัญ: getSubtotal() ทำหน้าที่เชื่อมโยงไปเรียกการคำนวณราคาของ Service ที่มันเก็บไว้ เพื่อคืนค่าเป็นราคาย่อยของรายการนั้น

3.7 Order (Class)

  • หน้าที่: จัดการคำสั่งซื้อภาพรวม และเก็บข้อมูลลูกค้า (ชื่อลูกค้า, เบอร์โทรศัพท์)
  • ความสัมพันธ์: เก็บ OrderItem หลายๆ ชิ้นในรูปแบบ Array
  • เมธอดสำคัญ: addItem() สำหรับเพิ่มรายการลงในออเดอร์, getTotal() สำหรับวนลูปคำนวณราคารวมทั้งหมดของทุกรายการย่อยในคำสั่งซื้อ

4. หน้าจอการใช้งาน (Frontend)

เพื่อให้ระบบทำงานได้จริงตามความต้องการ จึงมีการออกแบบหน้าจอระบบผ่านไฟล์ index.php และ style.css เพื่อแสดงผลฟอร์มการสั่งงานพิมพ์ที่สวยงาม ผู้ใช้งานสามารถกรอกรายละเอียด และระบบจะแสดง ใบเสร็จรับเงิน (Receipt) โดยการสร้าง Object จากคลาสต่างๆ ตามหลัก OOP มาคำนวณยอดเงินอย่างถูกต้อง
